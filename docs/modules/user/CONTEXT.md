# 用户模块上下文

本模块负责用户资料、关注关系和用户主页中的共同关注能力。用户主页博客内容由博客模块负责，本模块只提供关注关系及共同关注用户摘要。

## 模块目标

让登录用户能够查看自己与目标博主共同关注的用户，并保证关注关系、用户统计和 Redis 关注集合保持可用的一致状态。

## 负责范围

- 关注、取关和关注状态查询
- 用户关注数与粉丝数维护
- 用户关注列表集合的维护和缺失时重建
- 共同关注交集查询
- 返回共同关注用户的头像和昵称摘要
- 当前用户头像的编辑与公开资料同步

## 不负责范围

- 博客内容、博客分页和博客点赞
- 当前用户自己的主页整体管理（头像编辑除外）
- 共同关注用户的详细资料和推荐排序

## 核心概念

- **关注列表**：一个用户主动关注的用户 ID 集合。
- **共同关注**：当前登录用户与目标用户关注列表的交集。
- **共同关注摘要**：共同关注用户的 `id`、`nickName`、`icon`。
- **头像**：用户详情中可编辑且属于公开资料的图片信息，可以来自用户上传或默认头像。
- **默认头像**：系统提供的、具有稳定标识并可被用户选择的头像资源。
- **当前头像**：用户当前生效的唯一头像，公开资料和用户摘要读取同一值。

## 主要业务流程

1. 登录用户打开目标用户主页并点击“共同关注”。
2. 前端调用共同关注接口；未登录用户先跳转登录。
3. 后端确认目标用户存在，确保双方关注列表集合可用。
4. 对两个关注列表求交集，批量读取用户公开摘要并返回。
5. 没有交集时返回成功的空数组；查看自己的共同关注返回空数组。
6. 当前用户在资料编辑流程中选择上传头像或默认头像，预览后明确保存。
7. 保存成功后更新当前用户头像，用户主页和用户摘要读取最新头像。

## 数据模型

- `tb_follow(user_id, follow_user_id)` 是关注关系的持久化来源。
- `tb_user_info.followee` 保存主动关注数，`tb_user_info.fans` 保存粉丝数。
- Redis Set `follow:user:{userId}` 保存该用户关注的目标用户 ID，集合成员为字符串形式的用户 ID。
- `CommonFollowVO` 只包含 `id`、`nickName`、`icon`，不返回手机号和密码。
- `tb_user.icon` 保存当前头像引用；头像编辑不新增用户头像字段。

## 对外接口

- `GET /follow/common/{id}`：要求登录，返回 `Result<List<CommonFollowVO>>`。
- `PUT /follow/{id}/{toFollow}`：关注或取关成功后同步更新 Redis 关注列表。
- `GET /follow/or/not/{id}`：查询当前用户是否已关注目标用户。
- 头像临时上传接口：要求登录，校验图片后返回临时资源引用。
- 头像保存接口：要求登录，接收上传资源引用或默认头像 ID，更新当前用户头像并返回当前头像信息。

## 业务约束

- 目标用户不存在返回业务错误。
- 关注自己返回业务错误。
- 共同关注必须有当前登录用户；匿名访问不能计算交集。
- 关注和取关保持幂等；重复关注或重复取关均不产生额外关系。
- Redis 集合缺失时允许从 `tb_follow` 重建，避免历史关系在缓存上线后丢失。
- Redis 同步发生在数据库关系成功后；数据库失败时不写入集合。
- 头像更新只能作用于当前登录用户；默认头像 ID 必须来自后端允许列表。
- 头像上传只接受 JPG、PNG，单文件最大 5 MB；未保存临时资源保留 10 分钟后清理。
- 头像保存失败时保留原头像；用户上传头像替换成功后再清理旧文件，默认头像不参与用户文件清理。

## 已确认的设计

- 共同关注使用两个 Redis Set 的交集运算。
- 关注列表按用户分别存储，使用 `follow:user:{userId}` 作为集合键前缀。
- 共同关注列表只展示头像和昵称等轻量公开信息。
- 头像属于可编辑资料和公开资料；默认头像资源保持稳定访问地址。
- 头像内容按正方形处理，界面以圆形展示；第一版不提供交互式裁剪编辑器。
