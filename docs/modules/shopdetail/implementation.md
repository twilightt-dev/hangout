# 商详任务链实施与验收记录

日期：2026-10-19。依据 [context.md](context.md) 第 1～21 项已确认方案及用户 implement 指令实施。本次尚未 Git 提交、推送或创建 PR；没有操作真实数据库。

## 交付内容

| 层次 | 本轮实现 |
|---|---|
| domain | 店铺基础资料、业务分页和商详组合模型；近期口碑按用户去重、阈值及固定词典规则；周边坐标规则；仓储读取契约 |
| application | ShopDetailApplicationService、ShopDetailQueryService、六查询节点及 Assemble / Enrich；继承式上下文；区域状态与应用响应模型 |
| infrastructure | 直接 JDBC / MyBatis 查询店铺、优惠券、套餐、评价、推荐菜、博客与周边；复用现有 Redis 点赞集合，不调用旧 Service |
| facade / controller | GET /shop/{shopId}/detail；vouchers、blogs、related-shops 独立分页；套餐旧路径改分页；显式传入认证身份 |
| frontend | 一次聚合展示六区、局部重试、独立查看更多列表、加载更多；保留评价发布、推荐菜投稿和推荐、博客点赞、优惠券交易入口 |
| 文档 | 更新商详、店铺与根上下文，记录 [ADR 0017](../../adr/0017-商详采用首次展示任务链与独立分页.md) |

标签语料从首屏查询节点移至可选 Enrich 读取，分别处理两个来源的异常。这样语料阻塞不会使首屏评价和博客查询节点的全部写集丢弃。Enrich 整体超时则丢弃其全部增量，保留 Assemble 输出；局部异常返回 PARTIAL 或 FAILED，不伪装为空标签。

写操作继续走独立用例，成功后刷新对应列表或评分；不重新执行首次展示任务链。口碑标签在下一次详情读取时重新计算；未增加标签专用接口。查看更多从第 1 页独立开始，下一页失败保留已加载记录，重试原目标页；身份和店铺改变后忽略迟到结果。

## 接口兼容变化

GET /shop/{shopId}/setmeals 的 data 从套餐数组改为分页对象：
records、total、current、size、pages。默认 current=1、size=10，size 上限 50；每项仍含固定菜品和规则。本仓库前端及集成测试已同步，其他消费者也需适配。

GET /shop/{shopId}/detail 返回 shop 及各业务区域。区域使用 status、data、message；成功空结果与 FAILED、TIMED_OUT 分开。周边缺坐标或类型为 UNAVAILABLE；标签单来源成功为 PARTIAL。推荐状态单独以 recommendationStateAvailable 表达，博客点赞状态故障使用 null 并禁用操作。

## 部署与限制

- 本轮不新增业务表，依赖既有评价、套餐、推荐菜表和博客、店铺、用户、优惠券表；既有迁移是否已部署须核对目标环境。
- 未连接真实 MySQL、Redis，也未启动带真实服务依赖的完整后端。MySQL 行为、完整认证和上传、旧交易链路及生产延迟仍需实际环境验收。
- 默认查询阶段 2000ms、后处理 1000ms，可通过 shop-detail.query-timeout-ms 与 shop-detail.post-timeout-ms 调整。线程中断属于尽力取消，外部客户端仍需合理的连接和读取超时。
- 各查询只保证自己的事务快照；整页及跨请求分页不保证固定快照。热度变化可能导致跨页位次变化，前端加载更多按 ID 去重。
- 标签采用保守固定短语规则，问句、否定和不明确表述不计入；不是自然语言语义理解，也不代表官方认证或服务承诺。
- 没有新增聚合缓存、预热或数据库自动迁移；真实数据库操作、Git 提交和 PR 继续按 AGENTS.md 单独确认。
