# Domain 文档

本文件规定工程技能探索代码库时如何读取领域文档。

## 开始探索前读取

- 读取根目录的 `CONTEXT.md`；如果存在根目录的 `CONTEXT-MAP.md`，则按其中指向读取与当前主题相关的各个 `CONTEXT.md`。
- 读取涉及当前工作区域的 `docs/adr/` 中的 ADR。多上下文仓库还要检查 `src/<context>/docs/adr/`。

这些文件不存在时直接继续，不单独提示缺失，也不建议预先创建。领域建模技能会在术语或决策实际确定时按需创建它们。

## 文件布局

本仓库采用单上下文布局：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-事件驱动订单.md
│   └── 0002-写模型使用-postgres.md
└── src/
```

如果未来出现根目录 `CONTEXT-MAP.md`，则切换为多上下文规则：根目录的 `docs/adr/` 保存系统级决策，各上下文在 `src/<context>/CONTEXT.md` 和 `src/<context>/docs/adr/` 保存上下文级内容。

## 使用术语表

在 issue 标题、重构建议、假设或测试名称中使用领域概念时，采用 `CONTEXT.md` 定义的术语。术语表尚未覆盖所需概念时，记录该缺口并交给领域建模技能处理。

## 标记 ADR 冲突

如果输出与现有 ADR 冲突，明确指出冲突，不要静默覆盖。例如：

> 与 ADR-0007（事件驱动订单）冲突，但由于……值得重新讨论。
