# ADR 0015：店铺套餐独立建表并通过 DDD 提供展示查询

状态：已确认。日期：2026-10-18。

套餐代表明确列出菜品、数量和使用规则的固定组合，优惠券代表优惠权益，两者具有不同的业务身份。用户确认套餐独立建模，以 `tb_shop_setmeal` 和 `tb_shop_setmeal_item` 保存主信息及套餐内菜品，不复用优惠券表，也不建立跨套餐的共享菜品库。

沿用 [ADR 0013](0013-店铺评价在DDD模块独立实现.md) 的新增业务实现方式：domain 定义套餐模型和仓储接口，application 编排查询，infrastructure 提供 DO、Mapper 和仓储实现，facade 与 controller 提供门面和 HTTP 入口。代价是需要独立持久化映射与查询链路；其收益是套餐规则可以独立演进，不受优惠券及旧 service 业务实现约束。

第一版只提供游客可读的展示查询，一次返回上架套餐及全部固定菜品和纯文本使用规则。商详页面独立加载套餐，失败可重试，不阻断其他详情。交易与管理写接口不属于本期；用户明确要求后端商详聚合及共享任务链后续共同开发，因此当前不加入任务链节点或聚合返回模型。

业务规则及后续边界见[套餐模块上下文](../../doc/module/CONTEXT.md)。
