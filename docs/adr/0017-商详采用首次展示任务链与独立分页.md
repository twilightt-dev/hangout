# ADR 0017：商详采用首次展示任务链与独立分页

- 日期：2026-10-19
- 状态：按用户确认方案实施

商详包含六个展示区域。将所有读取堆在一个应用方法中，会把依赖顺序、超时与辅助查询失败处理混入业务规则。因此采用共享任务链：DATA_PROCESSING 并行取得六类基本事实，POST_PROCESSING 串行运行必需 Assemble 与可选 Enrich。默认阶段预算分别为 2 秒和 1 秒；只有基础查询与组装失败使整页失败。

Assemble 先生成可返回的领域组合对象。Enrich 取得独立近期语料、调用领域服务归并用户口碑并查询周边；发生异常或阶段超时时，不修改既有对象，而是丢弃该节点写集，保留组装结果。这样增强故障不会隐藏已经查询成功的列表。一次节点执行仍是整体提交单位，不能保证超时节点内部的部分结果可见。

页面首次展示使用一个聚合入口，查看更多从独立列表第 1 页开始，后续写操作仍调用独立业务接口，只刷新对应数据。套餐原接口同步改成分页对象，每项仍带明细与规则；这是已确认的接口契约变更，现有前端调用方同步修改，外部调用方升级时也须适配。

领域服务维护跨来源标签与周边规则，应用节点维护执行编排，基础设施直接读取业务表与现有 Redis 点赞集合。多语句仓储读取在调用线程内创建独立只读事务，整页不承诺一个数据库快照；不引入聚合缓存或预热来掩盖查询成本。真实 MySQL、Redis 与性能仍需目标环境验证。

2026-10-19 按用户要求进一步收拢领域能力：ShopDetailDomainService.getShopDetail 按教学项目形式直接调用仓储、给普通业务组合逐项赋值，再调用 enrichShopDetail。任务节点复用同一领域读取与业务计算能力。应用服务仅负责执行路径选择、引擎编排与执行状态检查；没有引擎 Bean 时调用同步入口，已执行链路失败时不重复查询整页。业务推导属于领域服务或其所属模型，响应字段转换留在 ShopDetailResult.from。

用户进一步要求取消领域 ShopDetailSection 包装，ShopDetailAggregate 只保存实际查询及衍生数据。任务链分项状态由应用层现有 SectionResult 和上下文维护，响应转换时与领域数据合并。同步路径直接传播仓储异常，不为强求与任务链故障表现一致而增加每字段包装；成功时业务规则一致。Assemble 的输出本身可被返回，Enrich 先复制再修改，通过新对象替换输出。上下文在执行完成后把尚未提交分项与最终节点诊断对应，避免把可选超时误报为空数据。列表加总数等读取组合仍在仓储边界，事务注解只作用于读取入口，不改变既有写用例。
