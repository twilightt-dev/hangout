# 评论点赞关系使用 Redis、计数保存在 MySQL

2026-10-14 用户确认新增一级评论点赞功能，选择 Redis 保存用户与评论的点赞关系，MySQL 保存评论点赞计数。Redis 关系作为事实来源，MySQL 计数允许短暂延迟并由服务自动重试或校正，采用最终一致性；两种存储没有共同事务。完整模型、接口和恢复流程已在同日审阅确认，源码已实现，数据库迁移与历史启用尚未执行。

业务采用切换语义：登录用户再次点击已点赞评论时取消点赞，允许给自己的评论点赞。只允许可见一级评论切换；不存在、被举报或禁止查看的评论拒绝操作，已有关系保留。评论列表展示数量和当前用户是否点赞，游客点击引导登录；第一版不包含回复、排行榜、点赞用户列表或通知。

前端防连点，不自动重发切换请求；超时或错误后重新读取实际状态，再允许操作。第一版不增加操作 ID 去重。Redis 不可用时评论列表和 MySQL 数量仍可展示，登录用户点赞状态为不可用且按钮禁用，写入返回暂时不可用；不能将查询故障显示成未点赞。

用户确认 Redis 原子完成关系切换与待同步标记记录，复用 job 模块将计数同步至 MySQL 并重试；允许增加计数同步字段，以恢复代次和代次内版本防止旧任务覆盖新结果。同步采用绝对数量条件更新，MySQL 提交成功后按版本确认 Redis 标记。备份恢复时先暂停并核对，再启用更高代次、重建待同步记录；第一版依赖 Redis 持久化与备份，不另存独立历史日志，完整丢失后的用户关系不可由 MySQL 数量重建。数据库尚未据此变更，恢复任务未在现有环境执行。实现补充 like_initialized 标记：行锁保护初始化与标记提交，即使首次点赞尚未同步计数，也不能因 Redis 缺失重新从零初始化；Redis 元数据另记录 count 来检查关系集合意外缺失。受控恢复工具和部署要求见 [部署与恢复](../design/评论点赞部署与恢复.md)。

上线前核对历史数据；非零 MySQL 计数缺少对应 Redis 关系的评论先暂停点赞，单独处理，后台不自动归零。NULL 且无关系可以视为 0。具体数据修复仍需单独确认目标、命令和影响。

领域采用评论实体与独立单用户点赞关系模型：Comment 管理身份和点赞资格，CommentLike 表达一个用户对一条评论的状态变化；点赞数是查询与同步使用的统计值，不将全部用户关系加载进评论聚合。

相比将关系和计数放在同一 MySQL 事务中，当前选择需要处理部分写入成功、请求结果不确定、并发以及 Redis 故障后的状态与计数恢复。普通 Spring 数据库事务不能回滚已完成的 Redis 写入。完整方案见 [评论点赞领域模型设计](../design/2026-10-14-评论点赞领域模型设计.md)，模块总览见 [CONTEXT](../../CONTEXT.md)。
