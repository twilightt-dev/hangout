# 博客与店铺访问统计采用展示上报和近似访客计数

用户确认博客统计累计 PV、店铺统计累计 UV，两项均包含游客，从功能上线开始统计，仅在对应详情页展示。博客 PV 使用整数计数；店铺 UV 使用 Redis HyperLogLog，接受近似误差。HLL 不保留访问者明细，后续无法直接从其恢复精确 UV 或访问名单。

访问记录以详情成功展示后的前端上报为触发条件。刷新和重新进入算新的展示，同一次展示的请求重试不重复计数；列表曝光和未展示的预加载不计入。详情接口还可用于卡片加载和页面数据刷新，直接在 GET 请求中计数会偏离展示口径。

访客统一使用浏览器持久随机 UUID，登录前后不变，不尝试按账号合并多设备；清除存储会产生新访客。这样避免匿名转登录或登录凭证失效改变去重身份，但统计的是浏览器标识而非自然人数。作者本人访问计入博客 PV。

累计统计仅保存于 Redis，不设过期时间；部署负责持久化和备份，业务表无法重建丢失的访问历史。博客 PV 计数与事件去重原子执行，事件记录保留 24 小时。两个公开 POST 上报接口接收访客与事件 UUID，返回最新累计值，客户端有限重试复用原事件。统计故障不影响浏览，无法读取的值展示“暂无统计”，不能当作零。

仅提供资源与参数校验和基础上报频率限制，不保证抵御恶意刷量；统计只用于热度展示，不用于奖励或结算。
